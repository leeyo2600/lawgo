이름으로 열을 찾으며, 업로드한 시트명·순서·기존 열 너비·행 높이·서식·다른 시트를 그대로 보존합니다. 빈 내용 칸만 채우고 기존 본문 및 원본 법령 표기는 유지합니다. 교정 내역과 미조회 사유는 수정사항에 기록하며, 기존 메모는 보존합니다. 서식만 남아 있는 빈 행은 처리 건수에서 제외합니다. 추가 통계 열이나 실패검토/실행요약 시트를 만들지 않습니다. 다른 시트가 있으면 첫 탭에서 처리할 시트를 선택합니다.

## LLM 호출·토큰 절약

- 일반 인용은 유사도 1 미만일 때 교정을 유지합니다. 단, `제34조 5` 같은 모호한 인용은 첫 교정 호출을 생략하고 실제 후보 본문 비교로 넘깁니다. 위치가 아예 없는 법령명도 조문번호를 추측할 수 없어 교정 호출을 생략합니다. 원문과 유사도 FLAG는 보존합니다.
- 국가법령의 같은 표기는 자치단체가 달라도 같은 모델의 교정 결과를 재사용합니다. 자치법규의 지역 구분과 후보 본문 비교의 행 문맥 구분은 유지합니다. 같은 요청 안의 중복도 합칩니다.
- 웹에서는 최대 10행을 미리 살펴보고, 생략·중복·캐시 항목을 제거한 실제 LLM 대상끼리 `llm_batch_size`만큼 묶습니다. 요청 ID는 짧게 전송하고 응답에서 원래 ID로 되돌립니다.
- 후보 본문 비교와 상위법령 보완은 모델·서버·프롬프트·실제 전송 내용이 같으면 LLM 응답을 재사용합니다. 보완은 필요한 종류의 법령 인용이 있는 문단과 앞뒤 문단만 보내며, 인용 근거가 없으면 호출하지 않습니다. 이후의 출처·조문 검증은 계속 수행합니다.
- 한 교정 배치의 복구 요청은 최대 5회입니다. HTTP 429·5xx는 배치를 쪼개지 않고 최대 2회 시도합니다. 공급자 오류가 확정되면 같은 실행의 뒤쪽 배치에 요청을 계속 보내지 않습니다. 이어하기는 새 클라이언트로 다시 시도하며 실패 응답은 교정 캐시에 저장하지 않습니다.
- `실행요약`에 사전 생략·보조 LLM 캐시 횟수와 보고된 입력/출력 토큰, 사용량 미보고 요청 수를 기록합니다. 단계별 원본 집계는 LLM 캐시 폴더의 `usage_*.json`에 모델별로 누적됩니다. 웹은 작업별 캐시, CLI는 지정한 캐시 폴더 기준입니다. 서버가 사용량을 보고하지 않은 요청이나 타임아웃의 실제 과금 토큰은 알 수 없으며 0토큰으로 단정하지 않습니다. BGE 임베딩은 로컬 계산으로 LLM API 토큰을 쓰지 않습니다.

## 처리 흐름

1. `input.json` 읽기
2. 상위법령/자치법규 참조문을 LLM으로 법령 인용표기 정규화
   - 예: `제4조의2 6항` → `제4조의2제6항`
3. Python 파서가 LLM 결과를 다시 `조 → 항 → 호 → 목`으로 검증
4. 국가법령정보센터에서 현행 법령/자치법규 검색
5. 실제 현행 조·항·호·목 존재 여부 확인
6. 해당 부분만 추출
7. `output/result.xlsx` 생성
8. 실패/검토 건은 `실패검토` 탭에 별도 저장

## 최초 설정


웹 실행은 OpenAI 공식 API 주소를 사용합니다. 모델과 배치 크기는 서버 설정에서 관리하며 웹 화면에는 API 키 입력창만 표시합니다.

```text
output/result.xlsx
```

## LLM/API 없이 구조만 확인

```powershell
python run_full.py --limit 10 --llm-mode rules --offline-api --output output/offline_10.xlsx
```

또는 `offline_10.bat` 더블클릭.

이 모드는 외부 LLM과 국가법령정보센터를 호출하지 않고 JSON 읽기, 파싱, 로그, Excel 출력 구조만 확인합니다.

## 실패/검토 정책

다음은 억지로 채우지 않고 `실패검토` 탭에 보냅니다.

- 입력된 근거의 오류만 검토합니다. 원본 빈칸은 기본적으로 빈칸 그대로 유지합니다.
- 법령명만 있고 조문 번호 없음
- `제0조`, `제.조`, 조 없이 항만 있는 등 안전하게 복구할 수 없는 표기
- LLM이 법령명 자체를 수정하거나 LOW confidence를 낸 경우
- 국가법령정보센터에서 법령/자치법규 후보를 찾지 못한 경우
- 현행명은 찾았지만 요청 조·항·호·목이 확인되지 않는 경우
- 자치법규 종류가 원본의 조례/규칙/훈령 등과 다른 경우

단순 `제` 누락, 띄어쓰기, 원형 항 번호 등은 LLM이 정규화한 뒤 실제 API 조문 존재 검증까지 통과하면 정상 처리합니다.

## 간편보기 실패 건 보완 및 별도 파일 병합

`repair_failed.py`는 7개 컬럼 간편보기에서 누락된 법령 종류와 조문을 각각 점검합니다.
세부 조회가 비어 있으면 동일한 현행 법령 전체 본문에서 같은 조문을 확인합니다.
호·목을 확인하지 못해 항 본문까지만 제공한 결과는 `PARENT_FALLBACK`으로 남기고,
제공 범위와 사유를 본문에 표시합니다. 항 자체를 찾지 못하면 다른 항이나 전체 조문으로 대체하지 않습니다.
별표를 확인하지 못한 경우 함께 요청한 조·항 본문은 보존하되 별표 미조회 사유를 따로 표시합니다.

병합은 일부 조문이 실패해도 확인된 다른 조문을 반영하며, 기존 정상 본문과 다른 법령 종류의 결과를 보존합니다.
이미지 태그 제거는 조회 성공 여부와 독립적으로 수행하고 이미지 본문 미확인 사유를 표시합니다.
번호 해석 및 모호한 조·항 비교 정책은 변경하지 않습니다.

```sh
.venv/bin/python repair_failed.py audit '/경로/기존간편보기.xlsx' --plan output/failed_only/new_plan.json
.venv/bin/python repair_failed.py run --plan output/failed_only/new_plan.json --state output/failed_only/new_state.json --max-llm-calls 30
.venv/bin/python repair_failed.py merge --plan output/failed_only/new_plan.json --state output/failed_only/new_state.json --output '/경로/간편보기_보완본.xlsx'
```

기존 파일을 보존하려면 마지막 명령에 **다른 파일명의 `--output`**을 지정합니다.
새 파일은 정상 결과와 보완 결과를 모두 포함하며, 원본 입력 컬럼·행 순서·서식을 유지합니다.
이미 존재하는 출력 파일은 덮어쓰지 않습니다. 실행 중단 시 같은 plan/state로 `run`을 다시 실행하면 저장된 결과 이후부터 진행합니다.
